# Безпека

## Порядок перевірки

Кожне нове TCP-з'єднання та кожен UDP-пакет порівнюється з увімкненими правилами, упорядкованими за зростанням `priority`, а за однакового пріоритету — за зростанням `id`. Перше відповідне правило визначає `allow` або `deny`. Якщо відповідності немає, застосовується `default_action`, за замовчуванням `deny`. Зміни правил діють одразу на наступні з'єднання/пакети. Встановлені TCP-з'єднання продовжуються за початковим рішенням і не перериваються після зміни правила.

## Конфлікти

Аналізатор розрізняє точні дублікати, однакові умови з протилежними діями, часткові перекриття та випадки повного затінення нижчого правила. Часткове перекриття лише повідомляється й не спричиняє автоматичної блокади. Для рівних умов порядок усе одно детермінований: пріоритет, потім ID.

## API та призначення трафіку

HTTP API прив'язано до `127.0.0.1`; його не можна виставляти на `0.0.0.0`. На кожному запуску генерується випадковий токен, потрібний для POST/PATCH/DELETE; токен показується один раз у консолі й не записується у файл чи журнал. Не передавайте його іншим процесам/користувачам і не зберігайте у Git. Доступ до локальної сесії Windows слід обмежити обліковим записом користувача та захистом пристрою. Не використовуйте тунелювання API чи перенаправлення порту на зовнішню мережу.

Кожен проксі слухає тільки loopback. Клієнт не передає адресу призначення: вона задається адміністратором у `config.json`, тому сервіс не є довільним відкритим проксі. Зовнішній target можливий лише при явному `allow_external_target: true` для конкретного сервісу.

## Межі та рекомендації

Це проксі-рівень користувача, він бачить лише TCP/UDP трафік, спрямований до налаштованих портів проксі. Це не системний Windows Firewall, не WFP-драйвер і не фільтр усього вихідного/вхідного трафіку ОС. Він не змінює системні правила Windows Firewall. Використовуйте IPv4 CIDR; порти задаються точно або `null` для будь-якого порту. Журнали містять метадані з'єднань без вмісту повідомлень. Захищайте файли конфігурації та журналів ACL Windows і не додавайте токени чи приватні дані до Git.
